# Display

Changes how the device looks and which language and time zone it uses. Use it to test dark mode, large text, animations and localisation without opening device settings.

| | |
|---|---|
| **Works on** | Android emulator and phone (some rows), iOS simulator. Physical iPhones show "not supported". |
| **Needs** | `adb` for Android, `xcrun simctl` for iOS simulators. It does not use `mobilecli device settings apply`. |

## Use it

1. Open the **Display** tab. It reads the device when shown; **Refresh** reads again.
2. Pick **Dark mode** (Auto, Light, Dark on Android; Light, Dark on iOS) and **Font size** (Small, Default, Large, Largest). Each change applies at once.
3. On Android, toggle **Disable animations**, **Show touches**, **Layout bounds**, **Pointer location** or **Don't keep activities**.
4. Choose or type a **Language** (BCP 47 tag) or **Time zone** (IANA id), then click **Apply**.
5. Click **Reset to defaults** to restore what this tab changed.

## Good to know

* The status text next to each control shows what the device reports, or the tool's own error text.
* Disable animations, Show touches, Layout bounds, Pointer location and Don't keep activities are Android only.
* On Android, setting the language replaces the whole language list with one tag. A confirm dialog appears if the device has two or more languages, and Reset can only bring back the first one.
* On an iOS simulator, a new language takes effect when an app restarts. The iOS time zone follows the Mac, so that combo is disabled.
* Reset values live only in the IDE session. Settings stay on the device after the tab or IDE closes.
* Not verified: the panel UI on live devices, physical Android devices, and other Android or iOS versions than those tested.

## Technical notes and what is not verified

<details>
<summary>Full reference text</summary>

The **Display** tab of Device Tools changes how the device looks, to test dark mode, large text and flaky-animation problems. Each control reads the device when the tab is shown (**Refresh** reads again), applies at once, and the status text next to it shows what the device reports afterwards or the tool's own error text. **Dark mode**: Auto, Light or Dark on Android (`adb shell cmd uimode night auto|no|yes`; a schedule mode such as `custom_schedule` shows as no selection), Light or Dark on an iOS simulator (`xcrun simctl ui appearance`). **Font size**: Small, Default, Large, Largest; on Android these write `font_scale` 0.85, 1.0, 1.15 and 1.3, on iOS the content size categories small, large, extra-extra-large and accessibility-extra-extra-extra-large (any other value on the device shows as a custom value). **Disable animations** (Android only) sets the window, transition and animator scales to 0; unchecking deletes the three settings. **Show touches** and **Layout bounds** (Android only) set `show_touches` and `debug.layout`. **Pointer location** and **Don't keep activities** (Android only) set `settings put system pointer_location` and `settings put global always_finish_activities` (1/0; unchecking writes 0, Reset deletes them; not verified on a live device, iOS shows "Android only"). **Reset to defaults** restores exactly what this tab changed on that device (values it remembered the first time it changed them, including "unset"); if this tab changed nothing yet it applies the platform defaults (Android: auto, 1.0, animation settings deleted, touches, layout bounds, pointer location and don't keep activities off; iOS: light, large). The remembered values live only in the IDE session, and settings stay on the device after the tab or IDE closes. Physical iPhones show "not supported". It uses adb and `simctl` directly, not `mobilecli device settings apply`, because that cannot read the state, does nothing on iOS animations and fails for iOS appearance. Verified on a Pixel 9 emulator (Android 17) and an iPhone 17 Pro simulator (iOS 26.5) with the commands above, and the layout bounds redraw of a running app. Not verified: the Show touches dots on screen (only the setting round-trips), the panel UI itself against live devices, physical Android devices (`debug.layout` and `settings put` may be refused), other Android or iOS versions, and iOS animations (there is no control; `ReduceMotionEnabled` writes but its live effect is unproven). **Language** and **Time zone** (the same tab, each with an editable combo and an Apply button; both show the device value when the tab is shown). Language presets: en-US, nl-NL, de-DE, fr-FR, es-ES, ja-JP and ar-SA (right-to-left); you can also type any BCP 47 tag (shape checked, the device may still not know it). Time zone presets: Europe/Amsterdam, UTC, America/New_York, Asia/Tokyo, Australia/Sydney, or type an IANA id (checked against the JDK's list). Android (checked on Android 17 / API 37): language runs `cmd locale set-device-locale <tag>` (live, no restart, running apps recreate their screens), read back with `get-device-locale`; the list is read from `settings get system system_locales`. WARNING: `set-device-locale` replaces the WHOLE language list with one tag, so a confirm dialog appears whenever the device list has two or more languages (decided from the live list, not from earlier changes), and Reset to defaults can only bring back the first one; re-add the others in Settings > System > Languages. Time zone runs `cmd alarm set-timezone <id>` (live, persists), read back with `getprop persist.sys.timezone`; if Automatic time zone is on in Settings the network may switch it back later. Both commands exit 0 for bad input, so the output text is checked and the value is read back; a mismatch is shown as an error. iOS simulator: language writes `AppleLanguages` (the new tag first, your other languages kept) and `AppleLocale` through `simctl spawn defaults write -g`; it takes effect for apps the next time they start (relaunch the app), while the Home screen/SpringBoard keeps the old language until the simulator or SpringBoard restarts (not done automatically). The iOS time zone follows the Mac, so the combo is disabled and the Mac's zone is shown. A write that fails without changing the device leaves no Reset baseline behind. Locale writes, Reset and Refresh do not overlap: Reset and Refresh wait (Reset is disabled) while a language or time zone write runs, and Reset restores the locale part even when the other Display values could not be read. Reset to defaults also restores what these controls changed: the Android time zone and first language, the iOS language list and locale exactly as read (keys that did not exist are deleted). For one app only, use Apps > Launch with options... > locale (nothing else changes). Verified by the scout on the Pixel 9 emulator (Android 17) and the iPhone 17 Pro simulator (iOS 26.5): the commands, read-backs and the iOS restore. Not verified: the new panel controls on live devices; Android older than 17 (`cmd locale set-device-locale` may not exist, the panel then shows the tool's error); that ar-SA flips the layout to right-to-left; whether `-u-` region extensions survive a change and restore; whether automatic time zone reverts a manual zone after a longer time; iOS 27 runtimes, the SpringBoard restart, and physical devices. Not implemented: Android per-app language button, restoring a multi-language Android list.
